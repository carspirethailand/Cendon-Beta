# Feedback release: scope and checks

This is an incremental fix on the existing Cendon layout, not a new design system.

## Changed in this release

- Garage records: shared bounded number/date/readable-name rules plus backend enforcement for changed symptoms, maintenance, trips and calendar prices. Existing unchanged history is preserved. This blocks obvious keyboard mashing, not every semantically meaningless sentence.
- Prices: caps distinguish reviewed exact model-year references from explicitly preliminary brand/service heuristics. No complete real model-year valuation corpus is claimed. Backend admin configuration supports reviewed HTTPS-source references.
- Car color: initial nonwhite car art uses a single SVG image-and-color operation; avoids white-first CSS-mask painting. Canvas tinting uses a bounded image size and no longer eagerly decodes every car type.
- Motion: removes targeted bounce/notification/menu entry effects and mobile backdrop blur while retaining voice visuals and intentional card flips. Chat rendering preserves unchanged message DOM, inputs and media on append.
- Desktop Chat: no floating/header bell; compact selected-car tools for real cost entry, parking and mechanic request. Existing desktop two-row composer is retained.
- Cost/logbook tool: editable fuel/service/trip form in Chat. Typed/voice log entries await a durable acknowledged append before claiming success. Decimal amounts and trip distance are retained, not silently rounded. Server append uses a request ID plus compare-and-swap for concurrent requests.
- Parking: own selected car only, with authenticated ownership check. Reads saved floor/note/time; computes approximate straight-line distance locally on request. Raw parking coordinates are not returned to the voice model. Unknown indoor route/floor is not invented.
- Valet: voice can propose public car details explicitly stated by the user; readback plus explicit yes/tap required. Typed car-detail and mileage changes also wait for server acknowledgement before updating the local display.
- Specifications: voice can read the same stored sourced library as Chat; more stored equipment and HTTPS provenance are exposed. No new research is started by this read.
- 18:00 Bangkok manual mileage reminder: both linked LINE and enabled device notifications, daily atomic claim prevents concurrent cron duplicates. Already-logged cars are skipped.
- Tracking: explicitly selected car/account bound to the session; switching either stops tracking. GPS distance is not silently converted into a confirmed odometer. User must enter the actual parked dashboard reading.
- Cache version bumped with all paired frontend assets; Windows static-help generation entry point corrected.

## Preserved from main, not reimplemented here

Multi-category mechanic services; existing Wrapped hidden-slide fix; Passport expenses; Garage call-mechanic/AI links; Home urgent/normal flip; Shop car selector; notification toggle; Studio profile/QR flip; category Match/Sort/map; desktop two-row composer.

## Remaining validation / limits

- Browser QA uses isolated sample data at desktop/mobile viewport sizes, not an authenticated production account or physical iOS/Android device. It is not proof of smoothness on every phone, OS lifecycle, or notification delivery on every device. Existing Wrapped fix still needs physical-device confirmation.
- Actual model-year repair/vehicle values and deep specification coverage need reviewed source data. Missing values remain missing; no fabricated full-car coverage or 100% accuracy claim.
- Phone GPS cannot prove driver identity or the physical car. Background web calls/tracking remain browser/OS-dependent. Reliable near-automatic multi-car identity needs explicit vehicle/Bluetooth/OBD or native integration with consent; not delivered by a cosmetic web patch.
- A lost append response followed by a new request ID is not universally exactly-once. Generic legacy state sync is still last-write-wins; the new append endpoint is concurrency-safe for appends.
- No paid services enabled. No production mechanic messages, applications, payments, customer records or notification recipients used for tests.
